# Схемы движка процессов

Машиночитаемые контракты движка процессов. Источник истины: этот каталог.

```
schemas/process-engine/
├── process-definition.schema.json   # схема определения процесса (v0.1)
├── examples/
│   └── purchase.process.json        # эталонный процесс «Закупка»
└── README.md
```

## Что описывает схема

**Модель исполнения**, а не доменную модель и не контракт агента.

| Слой | Что описывает | Где живёт |
|---|---|---|
| Доменные схемы | агрегаты и события (`PurchaseLaunched`) | `schemas/<домен>/` |
| **Определение процесса** | состояния, переходы, условия, таймеры, запреты | здесь |
| Агентные контракты | инструменты, права, схема результата LLM | появится позже |

Определение ссылается на домен только по именам (событие, команда, роль) и не содержит его структуру.

## Структура определения

| Понятие | Поле | Смысл |
|---|---|---|
| Состояние | `states[id]` | `start_event`, `end_event`, `wait`, `automated_task`, `user_task` |
| Переход | `transitions[]` | `from` → `to`, триггер в `on` (`event`, `decision`, `timer`) |
| Условие | `condition` | `all` / `any` из клауз `{field, op, value}` |
| Таймер | `timers[]` | дедлайн в состоянии и ветки по условию |
| Запрет | `forbidden[]` | явный запрет перехода с причиной |
| Роль | `role` | кто может инициировать переход |
| Действие | `action` + `args` | имя команды, исполняется через `CommandSink` |
| Аудит | `audit.include` | что писать в журнал решений |

## Версионирование

- `schemaVersion` — версия контракта. Несовместимое изменение схемы — новая версия.
- Определения привязаны к версии схемы, под которую написаны; старые определения не переписываются.
- `version` внутри определения — версия самого процесса (дата или semver), фиксируется при запуске инстанса.

## Валидация

Полная проверка требует `jsonschema`; без него выполняется только семантическая проверка.

```bash
cd ../tribe-engine
python3 scripts/validate_process_definitions.py
```

Проверяется:

- соответствие JSON Schema;
- уникальность идентификаторов переходов;
- существование состояний в `from`/`to`, у таймеров и запретов;
- наличие триггера у каждого перехода;
- достижимость состояний из `__start__`;
- наличие финальных состояний.

## Связь с Process IR

Схема совместима по смыслу с Process IR (AI Process Architect), но проще: только то, что нужно для исполнения. Моделирование остаётся в конструкторе, исполнение — в движке.
