# Полномочия и срок: мандаты

Документ описывает, как в Tribe выдаются и отзываются полномочия. Заменяет проверки «роль в группе» на модель `scope` + `mandate`.

## Зачем

Роль отвечает на вопрос «кто ты», мандат — «что тебе разрешено и до когда». Пока эти вещи слиты, временные структуры (комитет, стенд диспута, оргкомитет) живут дольше, чем нужно: права остаются, пока кто-то не вспомнит и не удалит группу.

Модель разделяет три механизма, которые часто путают:

| Вопрос | Механизм | Где живёт |
|---|---|---|
| Чем структура владеет | `owner_scope_id` на ресурсе | задача, проект, workspace, касса, предложение, очередь поддержки |
| Что ей разрешено | `capabilities` мандата | агрегат `Mandate` |
| Какие классы ресурсов допустимы | политика типа (`standing` / `temporary`) | модуль групп |

## Скоуп

**Scope** — всё, что может владеть ресурсами и выдавать полномочия:

- корень — сообщество (`community_id`);
- ребёнок — группа (`group.aggregate_id`).

Глубина делегирования — один уровень: сообщество выдаёт мандат группе, группа не выдаёт мандат другой группе. Вложенности групп нет намеренно: дерево требует ответа «наследует ли внук права деда», делегирование такого вопроса не создаёт.

## Мандат

```text
Mandate
  scope_id         — кому выдано
  issuer_scope_id  — кто выдал (сообщество или родительский скоуп)
  capabilities[]   — плоский список разрешённых действий
  constraints      — budget_limit, currency, in_scope, out_of_scope
  valid_from       — с какого момента действует
  valid_until      — до какого; null = бессрочно
  revoked_at       — когда отозван
```

События: `MandateGranted`, `MandateAmended`, `MandateRevoked`. Идентификатор детерминирован по скоупу: у группы один мандат, изменения — это `MandateAmended`, а не второй мандат.

**Инварианты:**

- мандат без capabilities не создаётся;
- `capabilities` дочернего мандата — подмножество мандата выдавшего (проверка при выдаче);
- отозванный мандат нельзя править;
- выдавшая сторона должна иметь действующий мандат, если это не сообщество.

## Проверка прав

Единая точка — `authorize(access, capability, scope_id)`:

1. если пользователь не активный участник сообщества — отказ;
2. если он `owner` или `admin` сообщества — разрешено (административный обход);
3. иначе смотрим capabilities, посчитанные для скоупа.

`authorize_any()` проверяет список скоупов (например, владелец проекта и его коллабораторы).

**Как считаются capabilities участника:**

```text
capabilities = role_capabilities(role) ∩ mandate.capabilities   — если мандат есть и действует
capabilities = role_capabilities(role)                          — если мандата нет
capabilities = ∅                                                — если мандат истёк или отозван
```

Пересечение важно: мандат ограничивает роль, а не повышает её. Участник группы не получает `group.manage` только потому, что мандат группы его содержит.

## Время

Правила, которые нельзя нарушать:

1. **В агрегате нет `now`.** Replay должен давать одно и то же состояние в любой день, поэтому хранятся только факты: `valid_from`, `valid_until`, `archived_at`.
2. **Истечение срока не зависит от процесса.** `authorize()` фильтрует мандаты по времени на каждом запросе. Если фоновая задача упала, права всё равно уже не действуют.
3. **Фон только убирает последствия.** Скан раз в час архивирует просроченные группы: освобождает доступы, снимает задачи, закрывает голосования. Пропущенный скан не даёт прав.
4. **Ленивая архивация.** Первая же мутация по просроченной группе архивирует её и отказывает.

## Capabilities

| Capability | Что разрешает |
|---|---|
| `group.manage` | Состав, настройки, архив группы |
| `group.participate` | Участие в жизни группы |
| `content.view` | Видимость контента группы |
| `workspace.access` | Доступ к workspace через группу |
| `project.manage` / `project.contribute` | Управление проектом / вклад в него |
| `proposal.decide` / `proposal.vote` | Управление голосованием / голос |
| `treasury.operate` / `wallet.operate` | Операции по кассе и кошельку |
| `support.handle` | Разбор заявок, адресованных группе |
| `guarantee.operate` | Операторские функции гаранта |

Список плоский и закрытый: policy-DSL не вводится.

## Кто выдаёт

| Скоуп | Выдающий | Срок |
|---|---|---|
| Постоянная группа | сообщество | бессрочно |
| Временная группа | сообщество (в будущем — родительский скоуп) | `valid_until = ends_by` |
| Ад-хок стенд, созданный процессом | сообщество по шаблону | срок кейса |

Мандат временной группы выдаётся при создании и отзывается при архивации. Продление — `MandateAmended` с новым `valid_until`; восстановление из архива — новый мандат.

## Миграция

Проверки `group_role(...)` заменены на `authorize(...)`; `group_role` больше не используется. Существующие группы без мандата работают по правилам роли (совместимость), скрипт `scripts/backfill_mandates.py` материализует им бессрочные мандаты.
