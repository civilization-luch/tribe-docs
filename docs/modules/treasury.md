# Модуль Treasury

Казна, бюджеты, финансовая прозрачность.

## Сущности

- **Fund** — фонд/касса (общий, резервный, на мероприятия)
- **Budget** — бюджет на период
- **Transaction** — приход/расход
- **Category** — статья расходов (коммуналка, ремонт, уборка, ивенты)
- **Balance** — баланс участника

## Actions

| Action | Описание |
|---|---|
| `create_fund` | Создать фонд |
| `deposit` | Пополнить казну |
| `withdraw` | Списать из казны |
| `set_budget` | Установить бюджет |
| `get_balance` | Баланс участника |
| `get_report` | Отчёт за период |
| `audit` | Аудит казны |

## Фонды

| Фонд | Назначение |
|---|---|
| Общий | Коммуналка, аренда, базовые расходы |
| Резервный | Непредвиденные траты |
| Мероприятия | Еда, декор, ивенты |
| Ремонт | Мебель, ремонт, обновления |

## Прозрачность

Все транзакции видны всем участникам сообщества (или группе дома). Участник может в любой момент посмотреть, куда пошли деньги.

## Примеры для кейсов

| Продукт | Фонды |
|---|---|
| **CoLive** | Коммуналка, ремонт, мероприятия, резерв |
| **CoSpace** | Аренда зала, инвентарь, маркетинг, ремонт |
| **CoSettle** | Земля, стройка, инфраструктура, резерв |
| **CoGuild** | Гранты на проекты, ивенты, инструменты |
| **CoOper** | Закупки, распределение прибыли, резерв, развитие |

## Операции казны

Каждая проводка описывает не только сумму, но и то, как деньги реально двигались.

| Поле | Значение |
|---|---|
| `type` | `deposit` — поступление, `withdrawal` — выдача |
| `method` | `bank`, `cash`, `crypto`, `other` |
| `custodian_id` | кто физически принял наличные (обязателен для cash-поступления) |
| `recipient` | кому выданы деньги (обязателен для любой выдачи) |
| `reference` | номер платежа, расписка, ссылка на транзакцию |
| `description` | свободный комментарий |
| `created_by` | кто провёл операцию |

## Наличные

- Наличное поступление нельзя провести без держателя: деньги в базе должны иметь физический адрес.
- Наличная выдача требует получателя, иначе непонятно, кому отдали.
- Банковская ссылка для наличных необязательна — вместо неё расписка или фото в `reference`.
- Баланс казны считается отдельно по каждому методу: «на счету» и «наличными на руках».

## Права

Пополнять казну может участник сообщества. Списывать — только владелец, админ или участник группы бухгалтеров (`wallet.accountant_group_id`).

## Взносы участников

Заявка на пополнение может быть зачислена:

- на личный баланс участника (по умолчанию);
- сразу в казну сообщества;
- в бюджет конкретной группы.

При подтверждении бухгалтер видит, куда пойдут деньги; валюта заявки должна совпадать с валютой казны.

## Движение средств (сверка)

Единый список объединяет проводки казны и заявки участников.

- `source` у проводки: `manual` — провёл человек, `wallet:<user>` — перевод с баланса, `claim:<id>` — подтверждённая заявка.
- `review` у записи подсвечивает то, что требует внимания:
  - `pending` — заявка ждёт подтверждения;
  - `no_reference` — банковское поступление без ссылки на платёж;
  - `duplicate_reference` — одна ссылка встречается в нескольких поступлениях;
  - `no_treasury_entry` — заявка с целевым счётом подтверждена, но проводки в казне нет.

Правило: каждая реальная проводка должна иметь одну запись с назначением. Если участник сначала положил деньги на баланс, а затем перевёл в казну — это две внутренние операции, связанные источником.

## Крипто-пополнения (без интеграции с блокчейном)

Пока нет API к сетям, крипта принимается тем же ручным способом, что и банковский перевод.

1. Админ сообщества задаёт реквизиты в казне: сеть, актив, адрес. На сообщество — один активный адрес; пользователь выбирает его из формы и не может вписать свой.
2. Участник создаёт заявку: метод `crypto`, сумма, **хеш транзакции обязателен**.
3. Бухгалтер проверяет в эксплорере сеть, актив, сумму, получателя и число подтверждений, затем подтверждает.
4. Подтверждённая заявка создаёт проводку казны `method=crypto`, `reference=<tx hash>`, `source=claim:<id>`.

Сверка: крипто-поступление без хеша флагуется как `no_reference`, повтор одного хеша — `duplicate_reference`.

Ограничение: платформа не проверяет транзакцию автоматически; ответственность за проверку лежит на бухгалтере.
