# Tribe — Vision Document

> **Продукты:** CoLive (коливинги) · CoSpace (пространства) · CoSettle (поселения) · CoGuild (гильдии) · CoOper (кооперативы) · Synergy (синергетические циклы)

## Миссия

Платформа-конструктор для самоуправляемых сообществ. Люди не просто получают доступ к ресурсу — они становятся участниками сообщества с правами, обязанностями, репутацией и совместным принятием решений.

## Ключевые принципы

- **Модульность** — каждое сообщество собирает свой набор модулей как LEGO
- **Самоорганизация** — инструменты для горизонтального управления, с гибкостью под любую модель (основатель → совет → полная демократия)
- **Региональная гибкость** — настраиваемая юридическая и финансовая логика под страну
- **Мультикейсовость** — коливинги, пространства, поселения, кооперативы — любые сообщества
- **Встроенная экономика** — платформа даёт сообществам не только управление, но и возможность зарабатывать

## Платные сервисы (монетизация)

Платформа даёт сообществам инструменты для создания и продажи товаров и услуг.

### LMS — Курсы

Любой участник сообщества может создавать и продавать курсы: профессиональные навыки, хобби, обучение управлению сообществом.

### Marketplace — Аренда и услуги

Участники могут публиковать и продавать:
- Свободные помещения / места (аренда)
- Личные услуги (обучение, консультации, помощь)
- Пространства под мероприятия

### Revenue — Распределение доходов

Доход от сервисов автоматически распределяется по настраиваемым правилам:

| Сторона | Назначение |
|---|---|
| **Автор / Исполнитель** | Тот, кто создал продукт или оказал услугу |
| **Участники сообщества** | Распределяется пропорционально вкладу в жизнь сообщества |
| **Казна сообщества** | В общий бюджет на развитие |

Доля участников сообщества распределяется по **взвешенной доле участия**: стаж, выполненные задачи, участие в голосованиях, платежи, репутация. Проценты настраиваются для каждого типа сервиса и могут меняться голосованием сообщества.

### Платформенный фонд

С каждой платной транзакции (курс, аренда, услуга) часть направляется в фонд платформы:

| Статья | Описание |
|---|---|
| **Хостинг** | Серверы, БД, CDN, S3, домены |
| **Разработка** | Оплата контрибьюторов ядра, код-ревью, тестирование |
| **AI Agent** | Вычислительные ресурсы, LLM API, инфраструктура агента |
| **Онбординг** | Курс «Как создать сообщество», шаблоны, поддержка новых сообществ |

Размер отчисления настраивается для каждого типа сервиса и может меняться голосованием Meta-сообщества платформы.

## Meta: сообщество платформы

Tribe управляется через Tribe. Сообщество разработчиков платформы работает как обычный пресет CoGuild:

- **Tasks** — баги, фичи, задачи по всем Co* продуктам
- **Projects** — группировка комплексных фич, milestones
- **Proposals** — голосования по приоритетам развития, приём контрибьюторов
- **Treasury** — бюджет на разработку, хостинг, инструменты
- **Billing** — оплата контрибьюторам, спонсорские поступления
- **LMS** — онбординг новых разработчиков, технические гайды
- **Content** — roadmap, changelog, обсуждения
- **Reputation** — рейтинг вклада участников в платформу
- **Documents** — контрибьюторские соглашения, лицензии

Каждая новая фича сначала тестируется на собственном сообществе. Платформа живёт по тем же правилам, которые даёт пользователям.

Инфраструктура управления платформой (Request → Agent → Task, Platform-сообщество, мониторинг, боты) описана в [docs/architecture/platform-ecosystem.md](docs/architecture/platform-ecosystem.md).

## Зонтичная структура

Tribe — зонт (umbrella) для независимых сообществ под общим протоколом.

### Federation (горизонталь)

- Все сообщества равны: Platform, CoLive, Synergy, CoSpace и т.д.
- Каждый зарегистрированный пользователь — observer Platform (гражданство зонта)
- Сообщества могут обмениваться событиями, репутацией и экономикой через **Federation Protocol** (TBD — зафиксировать контракт до реализации)
- Platform — один из узлов федерации, с особым статусом (владеет софтом, регистрацией, Agent'ом)

### Parent (вертикаль)

- Вложенность сообществ для пространственных/организационных кейсов
- Не связана с Platform — это отношение между дочерними сообществами
- Примеры: поселение → район (CoSettle), коливинг → корпус (CoLive)
- Родитель определяет политику: членство, бюджет, видимость (TBD — не реализуется сейчас)

### Принципы

- Federation и Parent — разные механики, не смешиваются
- Federation — opt-in, сообщество само решает, с кем federate
- Parent — иерархия с наследуемыми правилами (контракт фиксируется до реализации)

## Tribe Core: модель развёртывания

Каждое сообщество может работать как изолированный инстанс со своим сервером, БД, доменом и брендом.

### Single-tenant архитектура

```
Tribe Core (движок)
  ├── presets/          — CoLive, CoSpace, CoSettle, CoGuild, CoOper, Synergy
  ├── modules/          — все модули
  └── deploy/           — Docker Compose / Helm

Один инстанс = одно сообщество.
```

### Модель распространения

| | Community (OSS) | Premium |
|---|---|---|
| **Модули ядра** | Membership, Tasks, Content, Proposals, Reputation, Documents, Schedule, Bookings, Treasury | + Billing, Marketplace, LMS, Revenue, Registry, Projects |
| **Пресеты** | CoLive, CoSpace | + CoSettle, CoGuild, CoOper, Synergy |
| **Лицензия** | Open source | Private / подписка |

На старте всё в одном монорепозитории. Когда модули обкатаны — базовые уходят в открытый репозиторий, платные остаются приватными.

### Фазы

**Фаза 1 — монорепозиторий (сейчас)**
```
tribe/
├── core/
├── modules/     — все модули вместе
├── presets/     — все пресеты
└── apps/
```
Всё в одном репозитории, удобно для быстрого прототипирования и обкатки модулей.

**Фаза 2 — разделение**
```
github.com/tribe/core        (public, OSS)
  ├── modules/ — базовые (Membership, Tasks, Content…)
  ├── presets/ — community-пресеты
  └── core/

github.com/tribe/premium     (private)
  ├── modules/ — платные (Billing, Marketplace, LMS, Revenue…)
  └── presets/ — premium-пресеты
```
Базовое сообщество может работать бесплатно. Деньги, курсы, маркетплейс — с лицензией.
